# 台灣 50 成分股事件表（PIT universe）

`tw50_events.csv` 記錄台灣 50 指數的成分股**變動事件**，由
`stockta/data/universe.py` 重放成任一日期的成分股集合，用來消除倖存者偏誤。

## 目前狀態：**種子（seed），尚不可用於 PIT 回測**

```
python -m stockta.data.universe validate
```

現在會回報「事件表從未湊滿 50 檔」——**這是正確的行為，不是 bug**。
表裡目前只有兩次已查證的定期審核，缺少「起始成分股名單」與其餘約 80 次審核，
重放不出完整的 50 檔。在補齊之前，`members_asof()` 給出的集合不完整，
**不得**拿去跑回測；工具會如實反映這個狀態，不會安靜地給出一份看似合理的錯名單。

## 欄位

| 欄位 | 說明 |
|---|---|
| `effective_date` | 調整**生效日**（不是公告日）。定期審核於 3/6/9/12 月第一個週五公告、第三個週五收盤後生效 |
| `ticker` | yfinance 格式代號，如 `2330.TW` |
| `action` | `add`（納入）／`drop`（剔除） |
| `review` | `定期審核`／`臨時調整` |
| `source_url` | **必填**。沒有出處的列會被 `load_events()` 拒絕 |
| `note` | 公司名稱、公告日、疑義備註 |

`source_url` 強制必填是刻意的：這份資料是人工策展的，它的全部價值建立在
每一列都能被第三人查證。少了出處，它就只是一份看起來很專業的猜測。

### 代號與名稱錯位的風險

整理成分股名單時最容易犯、也最難發現的錯，是**代號與名稱錯位**。
本次實測中，多個自動摘要把 3034（聯詠）寫成台光電、把 2311 寫成日月光投控（實為 3711）。
錯位的池子在程式裡完全不會報錯，只會安靜地抓錯一檔股票的資料。

因此 `python -m stockta.data.pool_audit check` 一律**重新向資料源查證名稱**，
不接受人工輸入的名稱。任何要換上去的清單都應先過這一關。

## 補齊後要接的三個地方

補齊並通過 `validate()` 之後，以下三處都要改吃 as-of universe
（目前都用「今天的股票池」計算整段歷史）：

1. `features/market.py::build_market_context()` — 市場寬度的分母
   （**最容易被忽略**：這個特徵本身就被污染了）
2. `ml/cross_sectional.py` — 「贏過當日全池中位數」的中位數
3. `ml/dataset.py` / `ml/backtest.py` — 樣本 (T, d) 僅在 `T ∈ members_asof(d)` 時納入

並在 `config.py` 加 `UNIVERSE_MODE = "pit" | "fixed"`，寫入 artifact metadata
納入契約比對（比照 `MARKET_INCLUDE_REGIME` 的處理方式——切換必須重訓）。
