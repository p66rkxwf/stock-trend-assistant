# 測試集曝光帳本

> 「測試集被看過幾次？有沒有參與過特徵選擇、超參搜尋、早停？看過就不是樣本外了。」

這份帳本把 `experiment_log.md` 裡每一次動到測試期的紀錄逐筆列出並分類。
本專案的紀律一向是「選型與校準只用驗證期、測試期只做最終驗證」，
**這些內容原本就已在實驗記錄中誠實揭露**——這裡做的是把散落各處的揭露
收攏成一份可清點的帳，讓「看過幾次」變成一個有答案的問題。

- **產生方式**：人工整理自 `docs/experiment_log.md` #1–#9，新增實驗時須同步更新。
- **最後更新**：2026-08-16

## 總計

| 類別 | 次數 |
|---|---|
| 測試期被計算過的實驗 | 9（#1–#9 全部） |
| 其中**僅作最終驗證**（不影響任何決策） | 7 |
| 其中**影響了決策** | **2**（#5 延伸、#7a） |

「影響了決策」不等於作弊，但它確實讓那兩處的測試期數字**不再是無偏的樣本外估計**。
逐筆說明如下。

## 兩筆「影響決策」的細節

### #5 延伸（2026-07-18）：測試結果的防守性使用

驗證期 lstm 與 gru 平手（AUC 0.6706/0.6699、校準後 53.23%/53.25%，差距皆在噪音內），
兩者皆過 52.6% 採用門檻。裁決時參考了測試期：lstm 47.6% 持平、gru 45.1% 退步 2.5pp，
**因 gru 最終驗證退步而不部署**。

- 這是「拒絕上線已知退步的模型」，不是「用測試集挑出最好的模型」——
  方向上只會讓部署更保守，不會製造樂觀偏差。
- 但仍必須承認：**lstm 的 47.6% 因此帶有輕微選擇偏差**，不再是完全無偏的樣本外估計。
- 原記錄已如實揭露此事（"此為測試結果的防守性使用"），`config.py` 的註解亦然。

### #7a（2026-07-22）：測試期逐點掃描

跌門檻在驗證期做網格搜尋後，另在測試期以 0.45/0.50/0.55/0.60/0.65 逐點確認。
結論是**不採用**（測試期命中率隨門檻提高單調下降，反證了原假設）。

- 由於結論是否定的、且未依測試期結果選出任何參數，實質偏差極小。
- 但「在測試集上掃了五個點」這件事本身就是曝光，記在帳上。

## 真正沒被看過的保留集

上述每一筆都發生在**同一批歷史測試資料**上。要有真正無偏的樣本外估計，
唯一的辦法是資料在做決策時**還不存在**——本專案為此建立了兩條線上實證軌：

| 保留集 | 內容 | 曝光次數 |
|---|---|---|
| `predictions.db` `predictions` 表 | 每日線上絕對方向預測 vs 實際走勢 | **0** |
| `predictions.db` `rank_predictions` 表 | 每日 cross-sectional 分數 → 線上 Rank IC | **0** |

這兩條軌的性質決定了它們不可能被偷看：**預測在結果發生之前就已寫入、
且 append-only（同 ticker+基準日+版本只記第一筆）**。
截至 2026-08-13 已累積 441 筆到期的絕對方向紀錄（38.5%）與 11 天的線上 Rank IC
（+0.041，t=0.50，尚不顯著）。

數字目前並不漂亮——但它們是這份專案裡**唯一沒有任何選擇偏差**的數字，
而這正是它們的價值所在。歷史測試期的 44~47% 與線上的 38.5% 之間的落差，
本身就是「測試集曝光會讓數字變好看」最直接的證據。

## 規則（此後適用）

1. 選型、超參搜尋、門檻校準、早停——**一律只用驗證期**。
2. 測試期每次計算都要記進本帳本，並註明是否影響決策。
3. 若某次決策確實參考了測試期結果，必須在實驗記錄與本帳本**同時**揭露，
   並說明偏差的方向（樂觀還是保守）。
4. 對外報告引用歷史測試期數字時，一併引用線上實證數字。
