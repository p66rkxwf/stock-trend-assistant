# 倖存者偏誤研究

> 「你的 universe 是『今天還在上市的股票』嗎？下市、被合併的公司呢？它們正是輸家。」

- 最後更新：2026-08-16
- 狀態：**問題已量化並查證，修正的基礎建設已就位，PIT 資料尚未補齊**（見末節）

## 一、先講結論

`config.STOCK_POOL` 自稱是「台灣 50 成分股（2026-07 快照）」，被用來訓練與回測
**20 年**。查證後發現兩層問題，第二層比第一層嚴重：

1. **它連「今天的快照」都不是。** 名單有 49 檔（指數是 50 檔），
   且與已查證的兩次定期審核對不上（下節）。
2. **就算修正成今天正確的 50 檔，拿它回測 2006 年依然是倖存者偏誤。**
   這才是本維度真正要處理的問題。

## 二之二、「每季依市值重排，那怎麼可能確定？」

這個疑問很自然，但指數規則本身給了答案，而答案和直覺相反。

### 它不是每季重新排序，是帶遲滯的狀態機

FTSE TWSE Taiwan Index Series Ground Rules v3.5 §6.3.2 / §6.3.3：

| 動作 | 門檻 |
|---|---|
| 納入 | 市值排名**升到第 40 名或以上** |
| 剔除 | 市值排名**掉到第 61 名或以下** |

兩個門檻不一樣，中間的**第 41～60 名是緩衝帶**。同樣排在第 50 名，
原本在裡面的留著、原本在外面的進不來。規則自己寫明目的是
"designed to provide stability in the selection of constituents"。

這帶出兩個結論：

**結論一：不能靠「把當時的市值排序取前 50 名」重建歷史成分股。**
這是最誘人的捷徑，而它是錯的——因為成分資格**取決於前一期的狀態**，
不是當期市值的函數。在緩衝帶裡它會系統性地猜錯，而且錯得很安靜。
（何況還有 free-float 調整、流動性檢核、候補名單等規則會再改變結果。）

**結論二：正因為有緩衝帶，每季的異動很少（通常 1～4 檔），
所以「重放事件」是可行的。** 20 年約 80 次審核，是一份可以列舉完的離散清單，
不是連續問題。**每季調整讓這件事變簡單，不是變難。**

### 所以「確定」的方式是：記錄公告，而不是重算規則

規則有 free-float 調整、流動性檢核、候補名單、臨時調整等裁量空間，
自行重算不可能完全複製官方結果。**唯一的事實來源是官方公告的異動明細**，
我們的工作是忠實記錄它，再用**不變式**檢查有沒有抄錯：

| 不變式 | 依據 | 實作 |
|---|---|---|
| 任一時點恰好 50 檔 | §6.3.5 明訂維持固定檔數 | `validate()` 規模檢查 |
| 定期審核生效於當月**第三個星期五** | FTSE 公告用語 | `third_friday()` + `validate()` |
| 不得先剔除後納入 | 邏輯自洽 | `_replay()` 拋 `UniverseError` |

第二條上線當天就抓到一個錯：財經報導把 2026-06 的生效日寫成 6/18，
但當月第三個星期五是 **6/19**（且 2024-12、2025-12、2026-03 三次都對得上規則）。
這種差一天的錯誤靠肉眼根本看不出來。

### 對「線上名單」的結構性結論

既然成分股每季會變，**把名單寫死在 `config.py` 裡就是錯的資料結構**——
它從寫下的那一刻起開始腐壞，而腐壞沒有任何錯誤訊息。

已加入 `STOCK_POOL_ASOF`（最後一次真正核對的日期）與
`pool_staleness()`，`python -m stockta.data.pool_audit events` 會算出錯過幾次審核。
現況：**自 2025-07-01 以來已錯過 4 次定期審核。**

> 註：`STOCK_POOL_ASOF` 記的是「最後一次與官方名單核對」的時點，不是檔案修改日。
> 在補上官方名單之前不得往後改——改成今天不會讓池子變新，只會讓警訊消失。

## 三、偏誤的形態：不是「還沒上市」，是「還不是贏家」

用資料起始日盤點今天的 49 檔（取自 `data_cache/MANIFEST.json`）：

| 最早有資料的年份 | 檔數 | 累計 |
|---|---|---|
| 2004 | 43 | 43/49 |
| 2005 | 1 | 44/49 |
| 2009 | 1 | 45/49 |
| 2011 | 1 | 46/49 |
| 2012 | 1 | 47/49 |
| 2014 | 1 | 48/49 |
| 2017 | 1 | 49/49 |

2012 年後才有資料的只有 3 檔：緯穎(2017)、上海商銀(2014)、世芯-KY(2012)。

**這個結果本身就是重點。** 43/49 在 2004 年就已上市，所以偏誤的主要來源
**不是**「用了當年還不存在的股票」——那種偏誤只影響 3 檔。真正的問題是：

> 台泥、中鋼、台塑 2004 年就上市了，**而且當年就在台灣 50 裡**；
> 世芯-KY 2012 年上市，卻是最近幾年才擠進去的。
> 用今天的名單回測 2010 年，等於在 2010 年就知道世芯-KY 未來會變成大型股。

這是倖存者偏誤裡**比較危險的那一種**：它不會在資料裡留下缺值，
不會讓程式報錯，只會讓回測結果變好看。用「上市日」完全偵測不到它，
只有靠**當時的成分股名單**才看得出來。

而且方向很明確：指數的規則就是「市值前 50 大」，被納入的必然是**漲上來的**，
被剔除的必然是**跌下去的**。用今天的名單回測過去，等於系統性地挑到贏家。

## 四、修正的基礎建設（已完成）

| 元件 | 狀態 | 說明 |
|---|---|---|
| `data/universe.py` | ✅ | 事件表重放為任一日期的成分股集合 |
| `members_asof(d)` | ✅ | as-of 查詢，介面對齊 quant 平台的 `universe: dict[date, set[str]]` |
| `all_tickers_ever()` | ✅ | **含已下市／被剔除者**——抓價格資料時該用的清單 |
| `validate()` | ✅ | 規模檢查（永遠 50 檔）＋順序矛盾檢查 |
| `tests/test_universe.py` | ✅ | 12 條測試，含「漏一次納入」「重複納入」「先剔除後納入」等錯誤情境 |
| `data/universe/tw50_events.csv` | 🟡 **種子** | 只有 2 次已查證的審核 |

規模檢查是這裡最有效的一招：台灣 50 永遠是 50 檔，重放後不是 50 檔就代表
事件表有缺漏。這比人工核對名單可靠得多，也是為什麼現在
`python -m stockta.data.universe validate` **會回報失敗**——它如實反映
「資料還沒補齊」，而不是給出一份看似合理的錯名單。

## 五、還缺什麼

1. **起始成分股名單**：需要某個基準日的完整 50 檔當錨點。
2. **2006–2025 約 80 次定期審核的異動明細。**
3. 補齊後：接進 `build_market_context()` 的寬度分母、`cross_sectional.py` 的
   當日中位數、`dataset.py` 的樣本篩選，加 `UNIVERSE_MODE` 契約旗標並重訓。

**取得難度（2026-08-16 實測）**：七個來源全部試過，沒有一個能給出可信的完整名單。

| 來源 | 結果 |
|---|---|
| FTSE review notices | PDF **不含**異動明細，一律指向 XLSX 附件（2014／2024／2026 三份皆然） |
| FTSE TW50 factsheet | 官方、資料日 2026-07-31，載明 50 檔，但**只列 Top 5** |
| 元大投信 0050 持股 | 官方、資料日 2026-08-14，HTML **只含前 5 大**，其餘 JS 載入 |
| 臺灣指數公司 | 不列成分股 |
| 維基百科 | 50 檔但**內部矛盾**（同時含 2026-06 的納入與被剔除的陽明、康霈）|
| MoneyDJ | 頁面停在 2016 年，且代號名稱錯位 |
| CMoney／口袋證券 | JS 渲染；自動摘要會把代號與名稱配錯 |

**一個具體進展**：找到 2026-03-06 公告的**年度審核**（FTSE notice `id=2618964`，
2026-03-23 生效）——這很可能就是貿聯-KY 在兩次審核之間被剔除的那一次。
已知的 notice id 清單記在 `backend/data/universe/README.md`，供日後有附件存取權時取用。

**同時發現的風險**：多個自動摘要把代號與名稱配錯（3034 聯詠被寫成台光電、
2311 被寫成日月光投控／實為 3711）。錯位的池子不會報錯，只會安靜地抓錯股票。
故 `pool_audit check` 一律重新向資料源查證名稱，不接受人工輸入的名稱。

## 六、在補齊之前，該怎麼引用現有數字

所有既有的回測與實驗數字（`experiment_log.md` #1–#9、`cross_sectional_report.md`）
都是在固定池上跑的，**帶有方向明確的樂觀偏誤**。引用時應一併說明這一點。

唯一不受此偏誤影響的是**線上實證**：`predictions.db` 的每日預測是在
「當下的池子」上做的，沒有用到任何未來的成分股資訊。這也是為什麼線上
38.5% 與歷史測試期 44~47% 的落差值得認真看待——倖存者偏誤是其中一個可能成因。
